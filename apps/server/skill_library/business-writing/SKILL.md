# Business Writing

## Before writing (decide silently, ask only if it changes everything)

- **Reader:** who, what they already know, what they care about.
- **Purpose:** inform, request, decide, persuade, apologise?
- **One-sentence message:** if you can't say it in one sentence, clarify first.
- **Action:** what should the reader do, by when?
- **Language and register:** match the user's language (Vietnamese, English…) and the relationship (formal to a client, direct to a teammate).

## Structure: bottom line up front

1. The point / request in the first 1–2 sentences.
2. Context only as much as needed.
3. Details: short paragraphs, bullets for lists of 3+, numbers and dates exact.
4. Clear next step with owner and deadline.

## Formats

- **Email:** subject that says the content ("Approval needed: Q3 budget by Fri 5 Dec"); greeting; ask first; ≤ 150 words when possible; one ask per email; sign-off.
- **Reply:** answer every question asked, in their order; quote briefly if needed.
- **Memo / report:** Title, To/From/Date, Summary (3–5 lines), Background, Findings/Options (with pros/cons), Recommendation, Next steps. Executive summary must stand alone.
- **Proposal:** problem → proposed solution → benefits (quantified) → cost/timeline → risks → ask.
- **Bad news / apology:** state it plainly early, take responsibility, what you're doing, what changes; no excess hedging.
- **Announcement:** what, who is affected, when, what they need to do, where to ask.

## Style rules

- Short sentences, active voice, concrete verbs ("we cut costs 12%", not "a reduction was achieved").
- Remove filler: "I hope this email finds you well", "just", "very", "in order to", "please do not hesitate".
- Numbers: specific, with units and sources; dates with weekday for deadlines.
- Consistent terms; define acronyms once.
- Neutral, respectful tone; no sarcasm; no ALL CAPS.

## Editing someone's draft

Keep their voice and facts. Return the improved version, then 2–4 bullets on the main changes. For long docs, offer a tracked-changes Word file via the `docx` skill.

## Sending

If the user connected Gmail, you can create a **draft** with the Gmail portal; never send without explicit confirmation of recipients and final text. Long or formal documents → `docx` skill.
